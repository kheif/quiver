## v1.6.0: finding skills in your own library

Two behaviours change. Read these first.

- **`search_skills` now searches only Searchable skills**, at most 10 matches (it searched the whole library, returned up to 50 and asked before loading). The assistant loads a Searchable skill without asking, so it searches only what you chose. A skill that is not assigned is still found by `quiver search` and the panel; `quiver add --source <name> --searchable --global` makes the skills of a source Searchable.
- **`quiver new`, `quiver import` and the first-run import of `quiver init` now make the skill Searchable** instead of on demand, and so do the panel's `n` and `i`. A skill that is already assigned keeps its level. `quiver add <id>` lists a skill instead. The MCP tool `create_skill` and `quiver fork` are unchanged.

### Searchable skills

- A fourth level between *Not assigned* and *On demand*. A Searchable skill is not listed at session start and not loaded; the assistant finds it with `search_skills` and loads it with `get_skill`. Set it with `quiver add <id> --searchable` (`--source <name> --searchable` for a whole source, `--global` for every folder).
- `quiver source add` asks once whether to make the skills of the new source Searchable (the default is no; `--searchable` answers yes).
- When the folder has a Searchable skill, the session-start text and the server instructions carry a short cue that tells the assistant when to look for one. It names no skill. On Claude Code the shipped build found the fitting skill in 20 of 20 runs of the main test (the threshold was 16), and made no search in 20 runs of a plain question. Other assistants get the same cue and are not measured yet; Claude Desktop drops the instructions and has no hook, so name Quiver there.
- `quiver status` says what the session-start listing costs: skills listed, characters and estimated tokens, always-on skills apart, and how many skills are Searchable. `quiver status -v` lists the ten longest entries with the command that makes each Searchable. The panel shows the same count.
- `quiver search --json` has a new field `level` next to `here`. `quiver list`, `where`, `show`, `status`, `doctor`, `sync`, `update` and the panel know the new level.

### Search

- The default engine, `words`, is now a ranked word search over names and descriptions.
- The optional engine `local` also searches by meaning, so "send a note to the team channel" can find a skill that shares no word with it. It runs a small model (all-MiniLM-L6-v2) inside Quiver, in plain Go: no server, no runtime, no background process, and a search makes no network call. It understands **English only**; a query in another language gets the `words` matches.
- `quiver engine setup` sets it up: it asks once, downloads the 91 MB model file over HTTPS from one pinned address, checks its SHA-256, builds the index, checks that the search finds one of your skills and switches to `local`. That download is the only network use. `quiver engine use words` switches back, `quiver engine remove` deletes the index and the model Quiver downloaded, `quiver engine reindex` rebuilds the index. A model file you place yourself in `~/.quiver/cache/models/all-minilm-l6-v2/` is accepted when its hash matches.
- Skills are embedded when a search needs them, not when they are added: the first search after a bulk add builds the missing part (the server and the panel build in the background and answer with `words` meanwhile).
- `quiver doctor` checks each link (model file, hash, index); `doctor --fix` repeats a missing step in a terminal. The first time you make a skill Searchable in a terminal, Quiver offers the setup once.

### Upgrading

This is a minor release: nothing is removed or renamed, no input of an MCP tool changes and every v1.5 file is still read. A registry with a Searchable skill is written as version 3, which v1.5 refuses (as v1.2 did with version 2 after v1.3); until the first Searchable skill is added, the registry stays at version 2. With no `state/search.json`, the engine is `words`, and no index or model folder exists until you use `local`.

Security: [docs/security.md](https://github.com/kheif/quiver/blob/main/docs/security.md) works through the risks of this release.
