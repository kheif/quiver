# Contributing

## Build and test

Quiver needs Go (the version in `go.mod` or later) and git.

```bash
make build              # bin/quiver
make test               # go test ./..., including the end-to-end suite in e2e/
make lint               # golangci-lint
go test -race ./...     # as CI runs it on Linux and macOS
```

`QUIVER_HOME` points Quiver at another library folder, so you can try changes without touching `~/.quiver`.

## How work is planned

[PROJECT.md](PROJECT.md) describes the product. The work is split into tasks in [tasks/](tasks/README.md), generated by `scripts/gen_tasks.py`: edit the script and run `python3 scripts/gen_tasks.py tasks`, not the task files. Open questions are in [tasks/backlog.md](tasks/backlog.md), technical decisions in [tasks/decisions.md](tasks/decisions.md).

## Pull requests

- Keep one change per pull request, with tests.
- Every command has unit tests; a user-facing flow also has an end-to-end test in `e2e/`.
- Update the README and the help text when behaviour changes.
