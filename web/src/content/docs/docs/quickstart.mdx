This guide takes you from a fresh install to a skill your assistant uses in one project.

**Before you start:** [install Quiver](/docs/installation/), and have Claude Code, Codex or Cursor installed. Other assistants work too; see [Assistants](/docs/assistants/).

<Steps>

1. **Set up Quiver.**

   ```sh
   quiver init
   ```

   This creates the library in `~/.quiver`. In a terminal, it then offers three steps, one at a time. Each can be skipped and run later:

   - register the MCP server and the session-start hooks with your assistants (`quiver install`),
   - import the skills in `~/.claude/skills`, for every folder,
   - import the skills in the current project's `.claude/skills`.

   `quiver init --yes`, or a run outside a terminal, only creates `~/.quiver`.

   <Aside type="note" title="Next release">
   In v1.3.0 this step is `quiver mcp install`, which registers only the MCP server. In the next release `quiver install` also adds a session-start hook for Claude Code, Codex, Cursor, Antigravity and VS Code, which is how always-on skills and the skill list reach the model.
   </Aside>

2. **Write a skill for a project.**

   ```sh
   cd ~/code/app
   quiver new release-notes
   ```

   Quiver asks `Register ~/code/app as a project?` and opens the new `SKILL.md` in `$VISUAL` or `$EDITOR`. Write one sentence in `description` on when the assistant should use the skill, and the instructions below the frontmatter. When the editor closes, Quiver commits the skill in `~/.quiver/local` and assigns it to this project.

   ```text title="Output"
   Created ~/code/app/.quiver.json. Commit it, so the project keeps its ID.
   Created skill release-notes in ~/.quiver/local/release-notes
   Assigned to app: release-notes
   ```

3. **Commit `.quiver.json`.**

   The file only holds the project's ID. Committed, it makes every clone of the project the same Quiver project.

   ```sh
   git add .quiver.json && git commit -m "chore: add the Quiver project ID"
   ```

4. **Check what the assistant gets here.**

   ```sh
   quiver status
   ```

   ```text title="Output"
   Project: app
   ID:      app-6ts23a
   Root:    ~/code/app

   Served in app:
     release-notes  project
   ```

5. **Use it.**

   Start Claude Code in `~/code/app` and ask for the task, such as *"write the release notes for this version"*. The assistant sees `release-notes` in Quiver's skill list and loads it. Restart the assistant first if it was already running when you registered the server.

   You can also run the skill yourself as a prompt: `/quiver:release-notes`. Text after the command is passed to the skill as the task.

</Steps>

<Aside type="tip">
`quiver` alone sums up the current folder in three lines, with a next step, before the command list.
</Aside>

## Add skills from a repository

Skills published in git repositories are added as **sources**:

```sh
quiver source add anthropics/skills --name anthropic
quiver add anthropic/pdf --global
```

The first command clones the repository and lists its skills, such as `anthropic/pdf`. The second serves one of them in every folder.

<Aside type="caution">
A skill gives instructions to your assistant and can include scripts it may run. Add only sources you trust, and read their skills before you assign them. See [Security](/docs/project/security/).
</Aside>
